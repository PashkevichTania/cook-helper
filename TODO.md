# TODO: защита ИИ-чата

Сейчас БД нет. В запросах Gemini явно разрешён только текстовый ответ
(`responseModalities: ['TEXT']`). Остальные меры ниже пока не реализованы.

## Нужна БД или Redis

- [ ] **Общий бюджет приложения:** согласовать суточный и месячный предел
  расходов; хранить единые счётчики для всех серверных экземпляров и сохранять
  их после перезапуска. Атомарно резервировать максимальную стоимость запроса
  до обращения к Gemini, затем сверять с фактическим расходом. Учитывать вход,
  ответ и thinking, тариф выбранной модели, ошибки и незавершённые запросы.
  При неизвестном расходе сохранять резерв; при недоступности хранилища
  блокировать платные обращения. Определить часовой пояс сброса лимитов.
- [ ] **Персональные лимиты:** единые ограничения частоты, запросов за сутки
  и одновременных генераций. Текущие 6 запросов/минуту и 2 одновременно
  действуют только внутри одного процесса и не являются общим бюджетом.
- [ ] **История расхода:** сохранять usageMetadata, модель, результат запроса
  и расчёт стоимости без текста переписки и секретов; добавить уведомления
  о приближении к бюджету. Получение usageMetadata само по себе БД не требует,
  но общий долговременный учёт требует хранилища.
- [ ] **Доверенная история диалога, если понадобится:** хранить её на сервере
  и проверять принадлежность пользователю. Сейчас роли и история приходят
  из браузера и могут быть подделаны; не использовать их как разрешения
  на действия.

## Нужна идентификация и общее хранилище лимитов

- [ ] **Авторизация публичного чата:** выбрать провайдера авторизации или
  собственную БД пользователей. Управляемый провайдер может хранить аккаунты
  сам; счётчики квот всё равно требуют БД/Redis.
- [ ] **Защита гостевого доступа:** подписанная сервером сессия, ограничения
  по IP и CAPTCHA при подозрительной активности. Подпись сессии и проверка
  CAPTCHA не требуют своей БД; общие счётчики требуют БД/Redis. IP и
  localStorage не считать надёжной идентификацией. Заголовок sec-fetch-site
  не защищает от прямых запросов скриптом.

## Можно сделать без БД

- [ ] Закрепить список разрешённых текстовых моделей на сервере; сейчас
  GEMINI_MODEL проверяется только по формату имени.
- [ ] Ограничить весь входной контекст по токенам, включая системную
  инструкцию и продукты. Текущие ограничения символов и байтов сохранить.
- [ ] Подобрать thinking и максимальную длину ответа для выбранной модели
  по реальным рецептам и стоимости.
- [ ] Уточнить системную инструкцию: кулинарная тематика, краткие ответы,
  отказ от огромных повторений и base64. Не считать промпт финансовой
  защитой: жёсткие лимиты должны проверяться сервером.
- [ ] Связать отключение клиента/кнопку «Стоп» с отменой запроса к Gemini.
  Уже потраченные токены отмена не возвращает.
- [ ] Проверить доступные ограничения и уведомления у провайдера API и
  хостинга; не считать уведомление о расходах жёстким пределом бюджета.
